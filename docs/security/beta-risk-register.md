# Beta Residual-Risk Register (BETA-076)

Companion to the [beta threat model](./beta-threat-model.md) and
[control map](./beta-control-map.md). This register is the single source of truth for residual
risk after controls are applied. **P0 rows block production promotion**: the corresponding checkbox
in [`docs/deployment/RELEASE_GATES.md`](../deployment/RELEASE_GATES.md) §3 points here, and a
release may not proceed while a P0 row is open without an explicitly recorded acceptance by the
security owner in that document's sign-off table.

Statuses: `open` (work defined, not done), `accepted` (knowingly carried, disclosure duty exists),
`mitigated` (control landed, row kept for audit history). Priorities follow the threat model
severities.

## Change protocol

1. New residual risks discovered during verification get the next sequential ID and a named owner
   plus proof link — never a silent fix or silent acceptance.
2. Closing a row requires the proof artifact (test name, command output reference, or commit) noted
   in the row before flipping status to `mitigated`.
3. Priority changes require security-owner sign-off recorded in the RELEASE_GATES sign-off table.
