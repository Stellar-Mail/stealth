# R2 Encrypted Object Storage

Large encrypted payloads — envelope bodies and attachment chunks — are stored in
Cloudflare R2 through the adapter in `src/services/storage/`. KV and Durable
Objects are not sized for these payloads; R2 is the object store for the beta
relay path (BETA-030 / #1937).

## Binding

`wrangler.jsonc` declares the bucket binding:

```jsonc
"r2_buckets": [
  {
    "binding": "STEALTH_OBJECT_STORE",
    "bucket_name": "stealth-mail-object-store",
    "preview_bucket_name": "stealth-mail-object-store-preview"
  }
]
```

Create the buckets before the first production deploy:

```sh
wrangler r2 bucket create stealth-mail-object-store
wrangler r2 bucket create stealth-mail-object-store-preview
```

The binding is required in production: `validateApiConfig` fails startup when
`STEALTH_OBJECT_STORE` is missing.

## Object naming

Keys are deterministic and content-addressed; a sensitive filename is never
used as (or placed inside) an object key:

- Envelope body: `envelopes/<messageId>/<sha256-digest>`
- Attachment chunk: `attachments/<messageId>/<sha256-digest>/<chunkIndex>`
- Staged (not yet finalized) object: `staged/<random-upload-id>`

Because the digest is a SHA-256 of the ciphertext, the same message content
always maps to the same key, which makes finalization idempotent without ever
revealing the plaintext or the original filename.

## Integrity and ownership

Writes go through a staged-then-finalized path:

1. `stage` writes the bytes under `staged/...` with a TTL and records the
   owner, media type, content length, and SHA-256 commitment as metadata.
2. `finalize` verifies, _before the object becomes readable_:
   - the stored bytes match the declared content length,
   - the stored bytes match the SHA-256 commitment,
   - the media metadata matches the declared content type (when supplied),
   - the actor finalizing is the recorded owner.
3. Only then is the object copied to its deterministic final key and the staged
   object deleted.

Every read re-verifies the SHA-256 commitment; a corrupted object is refused
rather than served. Reads are restricted to the recorded owner.

## Orphan cleanup

Partial uploads and abandoned staged objects expire safely:

- Each staged object carries an `expiresAt` timestamp (default TTL 24h).
- `cleanupExpired()` lists the `staged/` prefix and deletes every staged object
  whose expiry has lapsed, including objects whose metadata is unreadable.

The relay facade (`src/services/relay/object-store.ts`) exposes this journey to
the relay path: store envelope body / attachment chunk (stage → verify →
finalize), verified reads, deterministic key previews, and the cleanup sweep.

## Deployment order

1. Create the R2 buckets (above).
2. Add the `STEALTH_OBJECT_STORE` binding to `wrangler.jsonc`.
3. Deploy the worker. Startup validation now requires the binding.
4. Trigger `cleanupExpired()` on a schedule (Cron Trigger / DO alarm) so staged
   objects cannot accumulate.
