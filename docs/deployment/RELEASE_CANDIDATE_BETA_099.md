## 2. Freeze controls (operational loop)

The freeze admits **only approved blocker fixes**. No feature commits were added to
`release/rc-1.0.0` beyond the freeze tooling; the branch is sourced from a known
`main` commit `e541cfed`.

The automated loop is implemented in `scripts/release/rc-freeze.mjs`. It runs each
gate the same way `.github/workflows/ci.yml` does and writes the standardized
`gate-result-*.json` artifacts consumed by the Beta Release Gate Summary job, then
produces `docs/deployment/rc-evidence/release-gate-summary.{json,md}` (gitignored
CI artifacts; see the committed `RC_EVIDENCE.md` for the reviewable aggregation).

```bash
node scripts/release/rc-freeze.mjs --commit e541cfed1b6018cf0767fe42e7e4314800ebe608
```

## 4. Blocker triage

No open blocker was discovered in the locally-executable scope. Findings:

- **Pinned playwright drift (local-only):** `npm` resolved `1.61.0` vs pinned `1.61.1`.
  Owner: `platform/release`. Resolution: use `bun install --frozen-lockfile` (matches
  `bun.lockb`) in CI; no code change required. Not a candidate defect.
- The remaining required gates are owned by CI jobs and the protected `testnet`
  environment (see §2). Their results are produced by the PR CI run and the manual
  `beta-live-testnet.yml` workflow dispatch.

Every gate in §2 has a named owner (from `RELEASE_GATES.md`) and a reproducible command.
